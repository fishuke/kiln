# Spec #107: talk to Studio (ADR-013 phases 2 and 3)

Decision record: [ADR-013](../adr/0013-voice.md). Builds on Studio (ADR-012).

## Goal

A person presses Talk in a Studio chat and has a full-duplex spoken conversation through GPT-Live. Their words go to the chat they're in, verbatim. Turn summaries and the agent's questions are spoken back. When they ask about another chat or App, the same session reaches there and moves their screen. A hands-free view shows a big preview, the transcript and the needs-you list.

## Flow

```
browser ──offer SDP──▶ POST /api/v1/voice/sessions ──▶ GPT-Live POST /v1/live/sessions (team OpenAI key, delegation: client)
browser ◀──answer SDP──                              ◀── { session.id, transcript.sdp }
browser ══ WebRTC audio ══ GPT-Live
API ══ sideband WS (wss://api.openai.com/v1/live/sessions/{id}/attach) ══ GPT-Live
   transcripts, session.delegation.created ──▶ Conductor ──▶ Thinker (decision model, tool use) ──▶ runTool (Studio)
   Studio bus events ──▶ Narrator ──▶ say / think on the sideband
   client actions (focus, show) ──▶ GET /api/v1/voice/sessions/{id}/events (SSE) ──▶ browser moves the screen
```

GPT-Live never runs an OpenAI backend model. Kiln owns every action; the browser's data channel is used only for `session.started`, transcripts for display, and `session.close`.

## packages/voice

`src/types.ts` is the contract (already written). Implement:

- `src/gpt-live.ts`: `GptLiveProvider implements VoiceProvider`. `create` POSTs `{ session: { model: "gpt-live-1", instructions, delegation: { type: "client" } }, transport: { type: "webrtc", sdp } }` to `${baseUrl}/v1/live/sessions` with `Authorization: Bearer <key>`; expects 201 with `session.id` and `transport.sdp`. `attach` opens `${wsBase}/v1/live/sessions/{id}/attach` with the same bearer header and maps wire events to `VoiceEvent`, `VoiceCommand` to wire commands (`session.commentary.append`, `session.thinking.append`, `session.instructions.append` with `event_id` and `delegation_id`, each `content` clipped to 500 tokens ≈ 1800 chars; `session.input_audio.mute|unmute`; `session.close`). Wire parsing uses zod and ignores unknown event types. `fetch` and the WebSocket constructor are injectable for tests.
- `src/fake.ts`: `FakeVoiceProvider` and `FakeVoiceLink`: records commands, lets a test `emit` events.
- `src/thinker.ts`: `AnthropicThinker implements Thinker` (Messages API tool use, `@anthropic-ai/sdk`, prompt caching on system + tools, `tool_choice: any`, max_tokens small, streams and returns as soon as the tool-use blocks are complete); `FakeThinker` (scripted). Base URL/key/model injected (the API passes the gateway or the team/server Anthropic key and `KILN_DECISION_MODEL`).
- `src/conductor.ts`: `Conductor` handles one delegation: takes the person's words since the last delegation, the focus and the Studio status digest, asks the `Thinker`, runs the chosen `ConductorCall`s through an injected `runTool(name, input)` (Studio's `runTool` with `via: "voice"`), and returns `{ say?, think?, client?: ClientAction[] }`. Rules:
  - `relay { chat? }` → `send { chat: chat ?? focus.chat, text: <person's words verbatim> }`. Never the model's words.
  - `apply`, `restore`, `ship` need spoken confirmation: the first call returns a `say` asking to confirm and stores a pending action; it runs only when the next delegation's thinker returns `confirm { yes: true }`.
  - Tool errors become a short `say` ("I couldn't apply that: …").
  - `status` and `look` results are turned into a short `say` by plain code (title, summary, question), not a second model call.
  - Client actions from tool results (`focus`, `show`) update the session's focus and are returned for the browser.
- `src/narrator.ts`: `Narrator` maps a Studio bus event to `VoiceCommand | undefined` given `{ focus, quiet, idle }`: `studio.needs_you` → `say` (quiet → `think` + badge); `studio.turn_finished` in the focused chat or while idle → `say` "<title>: <summary>"; otherwise `think`; `progress` → nothing. Returns badges for the browser.
- `src/session.ts`: `VoiceSessionStore` over `@kiln/store` collection `voice_sessions` (the `VoiceSession` type), times from an injected Clock. Keeps the last 40 transcript lines.

Tests (vitest, fakes only, no network): wire mapping both ways; create request body; relay verbatim; confirmation round trip; narrator priority table; resume seeds the transcript as `think`.

## API: `apps/api/src/routes/voice.ts`

Registered as a route module in `routes/index.ts` with `routes` listed for OpenAPI. Scope `send` for writes, `read` for the stream. Not in `app.ts`.

| Method | Path                                 | Body / result                                                                                                                                                                                                                                                                                       |
| ------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/api/v1/voice/sessions`             | `{ sdp, app?, chat?, resume? }` → `{ id, sdp }`. 409 `no_openai_key` when neither the team's OpenAI model key nor the server's `OPENAI_API_KEY` is set. `resume` reuses the stored session (same team and user): a new live session is created and seeded with the transcript and focus as `think`. |
| GET    | `/api/v1/voice/sessions/{id}/events` | SSE: `client` (ClientAction), `transcript` ({ role, text }), `badge` ({ appId, chatId?, text, priority }), `state` ({ status, focus, quiet })                                                                                                                                                       |
| PATCH  | `/api/v1/voice/sessions/{id}`        | `{ focus?, quiet? }`: the person moved by hand or toggled quiet mode                                                                                                                                                                                                                                |
| DELETE | `/api/v1/voice/sessions/{id}`        | closes the live session (`session.close` on the sideband) and marks it closed                                                                                                                                                                                                                       |

The route holds the sideband link per live session in memory, wires `Conductor` and `Narrator`, and subscribes to `kiln.bus` for `studio.*` events of the session's team. Idle: after 120 s with no input transcript the input is muted (`mute`) and the state says `idle`; any new input transcript or a PATCH unmutes. Sessions end after 30 minutes. On `closed` the usage is recorded on the session. The provider and thinker are injected through `AppOptions`/the Kiln container with fakes in tests (like other adapters). The Studio events SSE already exists; voice reuses `runTool` from `@kiln/studio` and adds `"hands_free"` to the `show` tool's views.

Tests: create with fake provider (body, key lookup, 409), delegation → send verbatim via fake thinker, narrator through the bus, PATCH focus, DELETE closes, other team gets 404.

## Web: `apps/web`

- `src/lib/studio/voice.ts`: `useVoice()` hook: mic via `getUserMedia` on the Talk click, `RTCPeerConnection` with the `oai-events` data channel created before the offer, wait for ICE gathering (10 s max), POST the offer, set the answer, EventSource on the session's events, apply `client` actions with the router (focus → the App/chat URL, `show` → the workspace view, `hands_free` → the hands-free view), PATCH focus when the person navigates. End: send `session.close`, wait for `session.closed` (15 s fallback), then close and stop tracks. Resume: on reload the session id in `sessionStorage` is passed as `resume`.
- Talk button in `components/studio/composer.tsx` next to the dictation mic: idle / connecting / live (pulsing, mute and end controls) / error with the message (`no_openai_key` links to the team's model keys page). AI Elements patterns.
- `components/studio/hands-free.tsx`: big preview of the focused chat, live transcript, needs-you list from badges, quiet toggle, end. Opens on `show: hands_free` or the first focus move to another App; a button returns to the normal screen.
- Turns sent by voice already show the mic icon.
