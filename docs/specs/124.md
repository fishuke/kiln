# #124: GitHub Enterprise Server as the forge

## Why

Teams on GitHub Enterprise Server can't use Kiln's forge: the server never passes a host to `GitHubForge`, clone URLs and app install links are hardwired to github.com. Only login honours `GITHUB_OAUTH_URL` / `GITHUB_API_URL`.

## Goal

One server setting points every GitHub client at another GitHub host. github.com stays the default and nothing changes without the setting.

## Approach

`githubHosts({ web, api })` (packages/integrations, forge.ts) returns the web host and REST API, each derived from the other: github.com ↔ api.github.com, otherwise `<host>` ↔ `<host>/api/v3`. `GitHubForge` takes `webUrl` beside `baseUrl` and builds `cloneUrl` from the host. `githubAppInstallUrl` and the GitHub connection take the host. `KilnOptions.githubUrl` (engine) feeds app install links and the manifest action. `apps/api/src/config.ts` reads `GITHUB_URL` and `GITHUB_API_URL` once and passes them to the token and App forges, installation tokens, the merge gate, manifests, connections, login and account linking (`GITHUB_OAUTH_URL` still overrides login).

## Acceptance criteria

- AC1: With `GITHUB_URL=https://ghe.example.com`, clone URLs and API calls use `ghe.example.com` and `ghe.example.com/api/v3`.
- AC2: App install and manifest links use the configured host.
- AC3: Unset, everything uses github.com / api.github.com as before.
