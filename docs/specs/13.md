# #13: Runners without an image use the server's runner image

## Problem

`runners/*.yaml` without `image` were normalized to `node:22-bookworm` by the schema, and the factory wizard, the web
factory template and the bundled templates wrote that image explicitly. `node:22-bookworm` carries no harness CLI, so
agent runs on those runners fail before the harness starts. The Agent SDK (ADR-009) still runs the CLI in the sandbox,
so the image must carry it.

## Change

- `packages/schema`: `Runner.image` is optional after normalization (`image ?? platform.linux.dockerImage`); no
  hard-coded default.
- `packages/sandbox`: `SandboxSpec.runner` requires a resolved image (`Runner & { image: string }`).
- `packages/engine` (`runs.ts`): the image is resolved per run as runner image → team environment image →
  `KILN_RUNNER_IMAGE` → `node:22-bookworm`. `wizard.ts` writes `image` only when the caller gives one.
- `apps/web`: the factory template omits `image`; the runner dialog accepts an empty image (shown as Kiln's runner
  image) and the save action drops the key when empty.
- `factories/templates/*` and `factories/kiln-self`: runners drop `image: node:22-bookworm`.
- Docs: `infrastructure/sandboxes.md`.

## Not changed

Factories that already name `node:22-bookworm` keep it: an explicit image is the author's choice. Existing ones are fixed
by editing the runner (as done for Poe Bot).

## Tests

- schema: a runner without an image has no image after parsing; `platform.linux.dockerImage` still fills it.
- engine: a declared runner without an image runs on `defaultImage`; an explicit runner image wins over it.
- engine: the wizard's `runners/default.yaml` has no `image` unless one is given.
