# #142: Command guard never asks a person

## Why

A risky command (`ask_human`) opened a `command-approval` inbox question and paused the run up to 9 minutes. People cannot judge raw commands, so the question is noise. See ADR-016.

## Rule

| Verdict | Isolated sandbox (`docker`, `kubernetes`) | Host (`local`, host fallback, `direct` worker, unknown) |
| --- | --- | --- |
| `allow` | runs | runs |
| `ask_human` | runs, recorded | blocked, agent told to stay inside its workspace |
| `block` | blocked | blocked |

A cowboy Studio App stays unguarded.

## Approach

- `packages/sandbox`: `settleVerdict(verdict, backend)` is the one place the rule lives. `guarded()` and `withGuard()` use the sandbox's own `provider`; `SandboxSpec.askHuman` is removed. `CommandBlocked` for a host block carries `HOST_BLOCKED`.
- `packages/engine`: `runs.settleGuard(run, verdict, command)` applies the rule for the run's backend (its sandbox, else its worker) and records the `guard` event on the live run. `gates.askCommand` and `askHumanTimeoutMs` are removed.
- `apps/api`: `POST /api/v1/guard` returns `runs.settleGuard(...)`: `{ verdict: "allow" | "block", reason? }`. Without a run, anything but `allow` is blocked.
- `packages/harness`: the hook prints the guard's `reason`; `COMMAND_APPROVAL_MAX_WAIT_MS` is removed.
- `packages/cli` worker: only `allow` from the API runs a command.

## Acceptance criteria

- AC1: `ask_human` runs the command in a `docker` or `kubernetes` sandbox, with no gate and no wait.
- AC2: `ask_human` on `local` throws `CommandBlocked` naming the host and the workspace.
- AC3: `POST /api/v1/guard` applies the same rule and never opens a gate.
- AC4: Nothing opens a `command-approval` gate; stored ones still load and list.
- AC5: The run has a `guard` event for every `block`, host-blocked `ask_human` and let-through `ask_human`.
- AC6: ADR-016 and the docs describe the rule.

## Not in this change

Studio's approval card and its `approval` turn field (server and web) are now unreachable for new turns; removing them is a follow-up, as is `GateService.wait`.
