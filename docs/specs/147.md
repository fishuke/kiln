# #147: Sandboxes only

## Why

Kiln could still run an agent on the host (`backend: local`, the server default, a silent fall back, a `direct` worker). The owner decided every run is in an isolated sandbox. One code path, and the command guard needs no host/sandbox split. See ADR-017.

## Rule

| | Before | Now |
| --- | --- | --- |
| Default backend | `local` | `docker` |
| Runner `backend: local` | runs on the host | rejected on apply; a stored one fails the run with a clear message |
| Runner's backend not on the server | falls back to the host, setup skipped | the run fails and names what is missing |
| Docker not running | (host was used) | "Kiln needs Docker running to start a sandbox: ..." |
| `kiln worker --backend direct` | a directory on the worker's host | rejected |
| `ask_human` | runs in a sandbox, blocked on the host | runs, recorded |

## Approach

- `packages/sandbox`: `LocalSandboxProvider` leaves the package index. It becomes `FakeSandboxProvider` in `src/testing.ts`, exported as `@kiln/sandbox/testing`. `settleVerdict(verdict)` has no backend. `SandboxUnavailable` is thrown when the Docker daemon (or the cluster) cannot be reached. `Sandbox.hostDir` (only the Fake has it) replaces the `provider === "local"` checks for hashing a workspace. In local mode the Docker backend mounts the forge's repository directories so a sandbox can clone and push.
- `packages/engine`: no default `local` provider. `runs.sandboxProvider()` throws a clear error for a missing backend and for a stored `backend: local`. `settleGuard(run, verdict, command)` records and returns the verdict. `createTestKiln` registers the Fake as the `docker` backend.
- `packages/definitions` (protected): `validateTree(tree, { stored })` rejects `backend: local` unless the tree is a stored one being loaded. `packages/schema` keeps `local` parseable for that reason.
- `apps/api`: `KILN_SANDBOX` defaults to `docker`; `local` or an unknown value stops the server at start. Workers connect with `docker` or `kubernetes` only.
- `packages/cli`: `kiln worker` has no `direct` backend; `--one-shot` works with any backend.
- `apps/web`: no "Local" sandbox host.

## Acceptance criteria

See issue #147 (AC1 to AC8).

## Not in this change

- The harness hook still prints a guard `reason`, which the API no longer sends.
- `Runner.backend` still defaults to `docker` in the schema, so a runner without a backend fails on a Kubernetes-only server. Making it follow the server's backend is a separate change.
- Studio's approval card (already unreachable since #142).
