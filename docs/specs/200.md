# #200: Factory Architect

Your favorite coding agent writes your factory from your repo, merged PRs, tracker and chat, then backtests it on your own history.

## Why

A new team's best factory is already implied by how it works: the commands CI runs, what reviewers keep asking for, where requests come from, which labels mean "small". Today onboarding means a generic template edited by hand. The Factory Architect reads that evidence and writes the tree, and a backtest on the team's last merged PRs shows how the factory would have done before anyone trusts it with new work.

## Pieces

All three live in `packages/cli` (no server changes).

### `kiln scan [dir] [--json]`

Deterministic, offline repo profile (`scanRepo(dir): RepoProfile`):

| Field               | From                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `languages`         | marker files: package.json, pyproject.toml/requirements.txt, go.mod, Cargo.toml, Gemfile, pom.xml/build.gradle, composer.json                                                   |
| `packageManager`    | lockfile: pnpm-lock.yaml, yarn.lock, bun.lockb/bun.lock, package-lock.json, poetry.lock, uv.lock                                                                                |
| `commands`          | install, test, lint, typecheck, build, from package.json scripts (run through the package manager) or language defaults                                                         |
| `ci`                | `github-actions` (.github/workflows/*.yml), `gitlab-ci`, `circleci`, `azure-pipelines`, with the files                                                                          |
| `agentInstructions` | CLAUDE.md, AGENTS.md, GEMINI.md, .cursor/rules, .github/copilot-instructions.md                                                                                                 |
| `mcpSuggestions`    | dependencies and config: @sentry/* → sentry, grafana/loki → grafana, datadog → datadog, @linear/sdk → linear, jira → jira, @slack/* → slack, posthog → posthog, stripe → stripe |
| `runner`            | a suggested `runners/*.yaml` body: image family and setup commands                                                                                                              |

### `kiln bench from-prs --repo owner/name [--limit 20] [--out benchmarks/backtest] [--dir .]`

Pull requests come through `PullRequestSource` (`listMerged(repo, limit)`) with `GhPullRequestSource` (the `gh` CLI, so it reuses the person's GitHub login) and `FakePullRequestSource` for tests. `backtestSuite(repo, prs)` is pure and returns files:

- `suite.yaml`: `name: backtest`, `agent: implement`, one configuration `current`, every task.
- `tasks/pr-<number>.yaml`: `title`, `prompt` (the linked issue's body when the PR closes one, else the PR title and the problem part of its body; never the diff), `successCriteria` (items under an "Acceptance criteria" heading or task-list items, else one fallback criterion: the behavior the title describes works and the tests the reference PR added pass), `criteriaVisibility: judge`, `startingRepoRefs: [github.com:<repo>@<baseSha>]`, `referencePr: <url>`, `tags: [<size>]` by changed lines (xs ≤ 10, s ≤ 60, m ≤ 300, l above).

PRs without a 40-character base SHA, bot authors (dependabot, renovate) and reverts are skipped and listed.

### `kiln architect [dir] [--agent claude,cursor,copilot,all] [--force] [--print]`

Always writes `.kiln/architect.md`: the agent-neutral instructions. Wrappers point at it in each agent's native format:

| Agent                     | File                                                          |
| ------------------------- | ------------------------------------------------------------- |
| Claude Code               | `.claude/skills/kiln-architect/SKILL.md` (`/kiln-architect`)  |
| Cursor                    | `.cursor/rules/kiln-architect.mdc`                            |
| GitHub Copilot            | `.github/prompts/kiln-architect.prompt.md`                    |
| Codex, Gemini CLI, others | follow `.kiln/architect.md`, or pipe `kiln architect --print` |

Without `--agent`, wrappers are added for agents the repo already uses (their folders or instruction files exist), and Claude Code when none are found. Existing files are kept unless `--force`.

The instructions: (1) `kiln scan --json`; (2) read the last merged PRs and review comments for conventions and recurring review asks; (3) with the person's OK, read the tracker (Linear/Jira/GitHub issues) and Slack through the agent's MCP servers: sources, labels, sizes, how often tickets have acceptance criteria; (4) write the tree with `kiln init --template sdlc` as the base, adapting factory.yaml, agents, skills (conventions from reviews), automations (from real sources and labels), gates, scorers, runners (from scan) and MCP servers (from scan and the tracker); (5) `kiln bench from-prs`; (6) loop `kiln validate` until clean; (7) write `FACTORY.md` with each choice and its evidence; (8) show `kiln diff` and ask before `kiln apply`. Privacy rules: summarize, never copy secrets, customer data or private messages into files; skip Slack and the tracker unless the person agrees.

## Tests

`scan.test.ts` (fixture repos in a temp dir), `backtest.test.ts` (Fake source → files → `validateTree` on an sdlc tree), `architect.test.ts` (files written, detection, `--force`, `--print`), plus CLI wiring in `main.test.ts`.
