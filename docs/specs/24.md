# #24: Retry a spec, optionally with a different model

## Problem
A spec review offers only Approve and Request changes. When a spec is off track, or the spec run failed
(`spec-failed`, #21), there is no way to start over or try another model.

## Design
- Engine (`packages/engine/src/workflow.ts`): `retrySpec(gateId, { by, via, model? })` closes an open spec gate or
  `spec-failed` question as `expired` with `decision: "retry"`, clears the spec, resets the spec loops, records
  `workItem.specRetry` and reruns the spec stage. `specRetry.ignoreGates` and `specRetry.messagesFrom` keep earlier
  "Requested changes" notes and people's messages out of the new spec prompt; `specRetry.model` is passed as
  `overrides.model` to that spec run only and then cleared. `retryOptions(gateId)` returns the spec agent, harness,
  configured model, routers and the model that wrote the spec.
- The spec gate's text ends with `Written by <agent> (<model>)`; `workItem.spec.model` records it.
- Inbox items for these gates add a `retry` action.
- API (`apps/api/src/routes/inbox.ts`): `GET|POST /api/v1/gates/{id}/retry`, scope `decide:spec`, zod-validated
  model id or `router:<name>` (an unknown router is 400). Implemented outside the protected `gates.ts`,
  `state.ts` and `app.ts`.
- Web: the gate card shows Retry, then a model picker (the agent's model by default) and "Retry spec".

## Acceptance criteria
- AC1: Retry reruns the spec without earlier notes or the previous spec.
- AC2: An optional model applies to that spec run only; the agent definition is unchanged.
- AC3: The gate and work item record the model that wrote the spec; the activity log says who retried it.
- AC4: The API validates the model and requires `decide:spec`.
- AC5: Retry works on a `spec-failed` question.
