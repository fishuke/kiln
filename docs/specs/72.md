# #72: Pull requests written by the implement agent, with one attribution comment

## Why
Kiln wrote the pull request title and description from the request, so a reviewer read the request instead of what changed.

## Approach
- **Agent writes it.** The implement agent reports `pr: { title, body }` in `.kiln/result.json`: a conventional commit title and a Why / What / Verification body (implement prompt, result protocol, `github` skill). `reportedPullRequest` (runs.ts) validates it.
- **Kiln adds the rest.** The workflow opens or updates the pull request with the latest implement run's `pr`, then appends the evidence (screenshots, videos) and the work item, source and tracker links. Without a `pr`, the request-based description stays. The label `factory:<alias>` is unchanged.
- **One attribution comment.** The footer is gone. On `pull_request.opened` the integration hub posts one comment marked `<!-- kiln:attribution -->`: the factory alias, the requester, a link to the task, and (on GitHub) "Mention @kiln-factory on this PR to send it follow-up work." Before posting it lists the comments (new optional `Forge.listComments`, on GitHub and the Fake) and skips when the marker is there.

## Acceptance
- With a `pr` from the agent, the pull request has its title and body, then evidence and tracking links.
- Without one, the title is the request's and the body is today's.
- The pull request carries exactly one attribution comment, even when attribution runs again.
