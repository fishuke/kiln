How it works

The whole development lifecycle, automated

CI/CD is the assembly line that builds, tests and ships code people wrote. A software factory extends that line forward: agents plan the change, write it, review it and prove it works. Your CI/CD still runs on every pull request.

Intake

Issue, Slack thread or ticket

Triage

Foreman picks the shortest path

Spec

Acceptance criteria you approve

Build

Agent codes in a sandbox

Verify

Tests, video per criterion

Preview

A live URL you accept

Review & merge

Reviewed PR, a person merges

Agents do the work You approve at the gates Small, clear changes skip the spec

CI/CD

  • inputA commit a person wrote
  • coversBuild, test, deploy
  • defined inPipeline YAML in your repo
  • gateGreen checks and a code review

Software factory · Kiln

  • inputAn issue, a Slack thread, a ticket, a schedule
  • coversPlan, spec, write, review, verify, preview, then your CI/CD
  • defined inA factory tree in a repo you own
  • gateSpec approval, preview acceptance, a person merges

Customize everything

        
Ten building blocks. No black box.

        
Every decision your factory makes is something you can read, change and version. Start from a template, then make it yours.

      

      

        
agents/
Agents
Foreman, triage, spec, implement, verify, review, or your own role. Harness and model per agent.

        
pipelines/
Pipelines
Fix the stages, fan out per user story, loop verify → build until it passes.

        
gates/
Gates
Who approves, what evidence they see, when to nudge and when to park the work.

        
routers/
Model routing
Easy tasks to a small model, hard ones to the best. Or route by benchmark results.

        
automations/
Automations
Start work from issues, mentions, PR comments, schedules or any webhook.

        
skills/
Skills
Reusable know-how in SKILL.md, per factory or per agent, shared across teams.

        
decisions/
Typed decisions
Command guard and triage as typed questions with thresholds, LLM only as fallback.

        
policies/
Policies & budgets
Protected paths, two-approval files, denied actions, a cap per work item.

        
runners/
Runners & workers
Sandbox image, CPU and memory, setup commands, egress allowlist, your own machines.

        
scorers/
Scorers
Rubrics with labels and a passing score that grade a sample of every agent's runs.

Built for teams

        
Agents do the work. People stay in charge.

      

      

        
Factories as code
Agents, automations, pipelines, scorers and skills live in a Git repo you own. Changes are reviewed like code and apply on merge.

        
Sandboxed runs
Every run starts in a Docker or gVisor sandbox behind an egress allowlist. Every shell command passes a guardrail.

        
Agents never merge
Agents push only kiln/* branches with short-lived tokens. No agent identity can approve or merge.

        
Evidence on every PR
Test output, a video for each acceptance criterion and a preview URL are attached to the pull request.

        
Scorers and self-improvement
Scorers grade every run. Repeated failures turn into definition PRs, replayed against the failing runs first.

        
Cost you can see
Spend per agent, per run and per merged PR: compute, inference and platform, with team budgets.

FAQ

        
Questions

      

      

        
Is it really free?
Yes. Kiln is MIT licensed and has no per-run fee. You pay your model provider (or use your Claude subscription) and run it on hardware you already have.

        
Which models and agents can I use?
Claude Code with a Claude subscription, an Anthropic key or AWS Bedrock; Codex with an OpenAI key; OpenCode and Pi with OpenRouter, Gemini and others. Set the harness and model per agent, or route by task difficulty.

        
I'm moving from Warp Factories. Can I bring my definitions?
kiln import converts a v1alpha1 factory definition tree to kiln/v1, and a connected config repo in that format is converted on every sync.

        
Can an agent merge to main?
No. Agents push only kiln/* branches with short-lived tokens, and no agent identity can approve or merge. A person merges, or a merge gate you turned on does.

        
Where does my code go?
Into sandboxes on your own infrastructure (Docker, or Kubernetes under gVisor) with an egress allowlist. The only outside calls are the ones you configure, such as your model provider.

        
How big a team does it need?
One person can run it with pnpm dev. Teams use Docker Compose or the Helm chart, with RBAC, an audit log, budgets and spend limits.
